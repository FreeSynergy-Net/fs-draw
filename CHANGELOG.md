# Changelog

## 0.0.2

### English

- **The basics of the program.** A server (`fs-draw serve`, crate `fs-draw-server`) serves the draft contract `whiteboard.capnp` over a Unix socket (`draw.sock`) in front of `fs-draw-core`: boards are listed, made, renamed and deleted; the rest of the contract answers the explicit "not possible" and the support report says so. A client crate (`fs-draw-client`) holds the handshake (a server of another version is replaced, the contract version must fit), the lease that ends a server started by a frontend when the last frontend is gone, and the board calls.
- **A window.** The frontend `simple` (crate and binary `fs-draw-simple`, on fs-components 0.0.24) shows the name, the program icon (own drawing, MIT; `packaging/net.freesynergy.Draw.png` and `.desktop`), what works now and what comes; entries that do not work yet are locked with "coming". German and English. It opens even without a server and says why.
- **The starter `fs-draw`** (crate `fs-draw-bin`): without arguments it makes sure the server runs and starts the frontend; when the frontend says the server's contract does not fit (exit code 3), a message is shown and the standard frontend `simple` is started. `fs-draw serve` runs the server. `--version`, `--help`; an unknown option exits with 2. Also `fs-draw-simple --version` and `--help`.
- **Package metadata:** `packaging/frontends/simple.metainfo.xml` (AppStream addon of the frontend, ADR 0094 draft). The workflows `check.yml` and `release.yml` call fs-release at v0.0.10 (Linux only); `.fs-lock-sources.toml` is strict, one source per library.
- The workspace version is 0.0.2 (first release with packages) because the tag v0.0.1 (the engine alone) exists. `fs-draw-core` is unchanged except that its pins now come from the workspace (`fs-interfaces` v0.0.22 in place of v0.0.1, one source in the lock).
- Limits: nothing can be drawn in the window yet; contract: draft (`whiteboard.capnp`, not locked), the basics are released with this draft contract; the server already stores boards, the window does not use this yet; the frontend is found next to the starter (the manifest is not read yet). `fs-draw-simple` is a deb/rpm of its own; `fs-draw` depends on it (package name `fs-draw`; `[package.metadata.deb] depends`, `[package.metadata.generate-rpm.requires]` in `crates/fs-draw-bin/Cargo.toml`).

### Deutsch

- **Die Grundlage des Programms.** Ein Server (`fs-draw serve`, Crate `fs-draw-server`) bedient den Entwurfs-Vertrag `whiteboard.capnp` über einen Unix-Socket (`draw.sock`) vor `fs-draw-core`: Tafeln werden aufgelistet, angelegt, umbenannt und gelöscht; der Rest des Vertrags antwortet mit dem ausdrücklichen „nicht möglich“, und der Support-Bericht sagt es auch. Ein Client-Crate (`fs-draw-client`) enthält den Handshake (ein Server anderer Version wird ersetzt, die Vertragsversion muss passen), die Lease, die einen von einem Frontend gestarteten Server mit dem letzten Frontend beendet, und die Aufrufe für Tafeln.
- **Ein Fenster.** Das Frontend `simple` (Crate und Programm `fs-draw-simple`, auf fs-components 0.0.24) zeigt Name, das Programm-Symbol (eigene Zeichnung, MIT; `packaging/net.freesynergy.Draw.png` und `.desktop`), was heute geht und was kommt; Einträge, die noch nicht gehen, sind gesperrt und sagen „kommt noch“. Deutsch und Englisch. Es öffnet auch ohne Server und sagt, warum.
- **Der Starter `fs-draw`** (Crate `fs-draw-bin`): ohne Argumente sorgt er dafür, dass der Server läuft, und startet das Frontend; sagt das Frontend, dass der Vertrag des Servers nicht passt (Exit-Code 3), erscheint eine Meldung und das Standard-Frontend `simple` wird gestartet. `fs-draw serve` führt den Server aus. `--version`, `--help`; eine unbekannte Option endet mit 2. Ebenso `fs-draw-simple --version` und `--help`.
- **Paket-Metadaten:** `packaging/frontends/simple.metainfo.xml` (AppStream-Addon des Frontends, ADR 0094 Entwurf). Die Workflows `check.yml` und `release.yml` rufen fs-release in v0.0.10 auf (nur Linux); `.fs-lock-sources.toml` ist streng, eine Quelle je Bibliothek.
- Die Version des Workspace ist 0.0.2, weil das Tag v0.0.1 (der Kern allein) schon existiert. `fs-draw-core` ist unverändert, nur seine Pins kommen jetzt aus dem Workspace (`fs-interfaces` v0.0.22 statt v0.0.1, eine Quelle im Lock).
- Grenzen: im Fenster lässt sich noch nichts zeichnen; Vertrag: Entwurf (`whiteboard.capnp`, nicht gesperrt), die Grundfassung erscheint mit diesem Entwurf; der Server speichert schon Tafeln, das Fenster nutzt das noch nicht; das Frontend wird neben dem Starter gefunden (das Manifest wird noch nicht gelesen); `fs-draw-simple` ist ein eigenes deb/rpm; `fs-draw` hängt davon ab (package name `fs-draw`; `[package.metadata.deb] depends`, `[package.metadata.generate-rpm.requires]` in `crates/fs-draw-bin/Cargo.toml`).
